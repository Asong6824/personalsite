# 网站配色系统

本文记录「大盈若冲」当前网站的实际配色结构、使用范围与代码来源。它是一份现状基线：用于理解页面之间的颜色关系、判断新增颜色应落在哪一层，并为后续 token 收敛提供依据。

---

## 一、设计总览

全站以 **warm editorial（暖色编辑纸张）** 为视觉基线：米色背景、深炭灰正文、暖灰卡片和分隔线。四个频道共享这层底色，再通过局部强调色、排版、材质和动效形成差异。

当前配色可以分为五层：

1. **站点品牌层**：页面背景、全局导航和基础墨色。
2. **通用 UI 层**：表单、弹窗、图表、焦点环等组件 token，保留亮色/暗色两套冷灰天蓝主题。
3. **页面叙事层**：首页使用独立的深蓝黑文字与少量橙色、粉色信号色。
4. **频道表达层**：技术/生活共享暖色编辑色，金融使用绿与琥珀，创意使用玻璃光晕和紫色链接。
5. **内容可视化层**：文章内图表、地图和手绘组件按业务语义使用局部色板。

这些层级目前尚未完全收敛到同一套 CSS 变量。新增颜色前应先判断它属于哪一层，避免把文章图表中的业务颜色提升为全站品牌色。

## 二、全站核心色板

核心色定义在 `src/lib/site-theme.ts`，同时映射到 `src/app/globals.css` 中的站点及频道变量。

| 角色 | 色值 | 代码 token | 主要用途 |
|------|------|------------|----------|
| 页面背景 | `#F0EEE7` | `SITE_WARM_BACKGROUND`、`--site-page-bg`、`--channel-bg` | `html`、`body`、首页、频道页、文章页、Three.js 背景 |
| 纸张表面 | `#E2DBCE` | `SITE_WARM_SURFACE`、`--channel-card` | 卡片、标签、内容分区 |
| 高层表面 | `#D8D0C3` | `SITE_WARM_SURFACE_HIGH`、`--channel-card-hover` | Hover、边框、较深纸张层级 |
| 主墨色 | `#141413` | `SITE_WARM_INK`、`--site-nav-ink`、`--channel-ink` | 标题、正文、导航、主要图形 |
| 次级墨色 | `#68645D` | `SITE_WARM_MUTED`、`--site-nav-muted`、`--channel-muted` | 摘要、时间、注释、辅助文字 |

### 基础使用原则

- 页面外层默认使用 `#F0EEE7`，不要重新引入纯白作为正式页面主背景。
- 正文和标题优先使用 `#141413`，弱化信息使用 `#68645D`。
- 卡片层级优先使用 `#E2DBCE` 和 `#D8D0C3`，阴影不是主要层级手段。
- Three.js 场景使用 `SITE_WARM_BACKGROUND_THREE`（`0xf0eee7`）保持与 DOM 背景无缝衔接。
- React/Three.js 代码优先复用 `src/lib/site-theme.ts`；CSS 作用域内优先使用相应变量。

## 三、全局导航

导航采用核心暖色板的半透明衍生色，定义在 `src/app/globals.css`：

| 角色 | 当前值 |
|------|--------|
| 导航文字 | `#141413` |
| 次级/渐变文字 | `#68645D` |
| Hover 表面 | `rgba(226, 219, 206, 0.42)` |
| Active 表面 | `rgba(216, 208, 195, 0.78)` |
| Pending 表面 | `rgba(216, 208, 195, 0.90)` |
| 导航边框 | `rgba(104, 100, 93, 0.18)` |
| Focus 光圈 | `rgba(104, 100, 93, 0.35)` |

移动导航面板使用约 95% 不透明度的 `#F0EEE7` 并叠加背景模糊。导航状态主要通过表面深浅区分，不使用频道强调色。

## 四、通用 UI 语义色

`src/app/globals.css` 的 `:root` 与 `.dark` 还定义了一套基于 OKLCH 的通用组件 token。这套色板主要服务于通用 UI、表单、Popover、Sidebar 和图表，不代表正式内容页面的背景风格。

### 亮色模式

| Token 组 | 配色方向 | 用途 |
|----------|----------|------|
| `--background` / `--foreground` | 近白冷灰 / 深冷灰 | 未覆写主题的通用组件 |
| `--card` / `--popover` | 纯白 | 卡片、浮层 |
| `--primary` / `--accent` | 天蓝色 | 主操作和强调状态 |
| `--secondary` / `--muted` | 浅冷灰 | 次级表面与弱化信息 |
| `--destructive` | 红色 | 删除、错误和危险操作 |
| `--border` / `--input` | 浅冷灰 | 边框和输入表面 |
| `--ring` | 半透明天蓝 | 键盘焦点 |
| `--chart-1` 至 `--chart-5` | 天蓝和蓝灰梯度 | 通用图表 |

### 暗色模式

`.dark` 将通用 UI 切换为深冷灰背景、浅冷灰文字和更亮的天蓝强调色。需要注意：

- `html`、`body`、首页及主要频道仍显式使用 `#F0EEE7`。
- 技术、生活和金融文章样式也大多显式指定亮色。
- 因此当前暗色模式主要覆盖通用组件，并不是全站完整的深色主题。
- 新组件不能只依赖 `.dark` 存在就假定所在页面会变成深色背景。

## 五、首页配色

当前正式首页以统一暖背景承载 WebGL 叙事，但文字没有使用全站 `#141413`，而是采用更冷、更深的蓝黑色。

| 角色 | 色值 | 用途 |
|------|------|------|
| 场景与页面背景 | `#F0EEE7` | DOM、加载遮罩、Three.js scene、背景贴图 |
| 首页主文字 | `#0A0C20` | 标题、列表、连线、加载进度、页脚 |
| 首页弱化文字 | `rgba(10, 12, 32, 0.45–0.72)` | 说明、元信息、非活跃条目 |
| 图片占位表面 | `#E7E1D6` | 最新文章图片容器 |
| 观察卡片表面 | `rgba(247, 248, 241, 0.82)` | Observe 信号卡 |
| 观察说明绿灰 | `#42513B` | 信号卡图注 |
| Express 信号橙 | `#FF5A1F` | 表达网络的重点节点 |
| Canvas 渐变粉 | `#F7D7E9` | 局部运行时纹理过渡 |

首页的冷蓝黑使 WebGL 图形比普通文章更精确、数字化；橙色和粉色只作为叙事信号，不是全站操作色。首页实现位于 `src/components/home/`，结构说明见 `docs/homepage-design.md`。

`src/app/home.module.css` 中还保留一套 Blue Bottle 风格变量：深蓝 `#0077A3`、亮蓝 `#00A9E0`、暖纸张和暖灰表面。它主要供生活频道及旧式叙事组件复用，不应与当前正式首页的 `#0A0C20` 叙事色混为一套。

## 六、频道配色

### 技术频道

技术频道直接使用全站 warm editorial 基线：

| 角色 | 色值 |
|------|------|
| 背景 | `#F0EEE7` |
| 卡片 | `#E2DBCE` |
| Hover / 边框 | `#D8D0C3` |
| 标题与正文 | `#141413` |
| 辅助文字 | `#68645D` |

频道本身没有独占的高饱和强调色。彩色主要来自文章中的技术图表和手绘组件，详细现状见 `docs/sketchy-components.md`。

### 生活频道

生活频道与技术频道共享背景、卡片、墨色和边框，通过排版、光晕、旅行图片和 3D 内容形成差异。`src/app/home.module.css` 中的 scholarly 主题补充以下强调色：

| 角色 | 色值 | 用途 |
|------|------|------|
| 深蓝强调 | `#0077A3` | 主要按钮、重点状态 |
| 亮蓝强调 | `#00A9E0` | 次级强调、焦点环 |
| 按钮渐变深端 | `#005F82` | 深蓝按钮渐变 |
| 按钮浅文字 | `#F7F3EC` | 蓝色按钮上的文字 |

生活频道的蓝色是局部强调，不替代 `#141413` 正文。

### 金融频道

金融频道以暖背景为底，使用深绿和琥珀建立杂志及市场数据语义。

| 角色 | 色值 | 用途 |
|------|------|------|
| 页面背景 | `#F0EEE7` | 频道、专栏和文章背景 |
| 主文字 | `#1A1C19` | 标题、深色 CTA、引用卡 |
| 正文/次要文字 | `#444748` | 摘要、导航、正文 |
| 元信息 | `#747878` | 日期、英文副标题、空状态 |
| 主强调绿 | `#506354` | 数据编号、链接、标签、Hover |
| 浅装饰线 | `#C4C7C7` | 分隔、占位和弱化信息 |
| 主卡片 | `#F4F4EF` | 内容卡片、页脚、标签 |
| 次级卡片 | `#E3E3DE` | 次级专题、头像和占位 |
| 琥珀强调 | `#FFDEA5` | 精选标签、按钮、标题下划线 |
| 琥珀文字 | `#261900` | 琥珀表面上的文字 |
| 金色 Hover | `#D4AF37` | Footer 链接 Hover |

局部状态装饰还使用低透明度绿、琥珀和红色下划线。金融主实现是 `src/components/finance/FinanceHomeClient.tsx` 与 `FinanceColumnLayout.tsx`；`DataWall`、`DebugPanel` 等未挂载实验组件的深色配色不属于正式频道规范。

### 创意频道

创意频道保留全站暖背景，通过半透明玻璃、浅色光晕和更柔和的中性文字制造轻盈感。

| 角色 | 当前实现 | 用途 |
|------|----------|------|
| 页面背景 | `#F0EEE7` | 频道与文章外层 |
| 暖灰光晕 | `#E2DBCE` / 45% | 背景环境光 |
| 主标题 | Tailwind `neutral-900` | 频道标题和卡片标题 |
| 次级文字 | Tailwind `neutral-500` | 描述和辅助信息 |
| 玻璃边框 | Tailwind `neutral-200` / 低透明度 | 卡片和按钮边界 |
| 文章链接 | `purple-700` | 正文链接 |
| 链接 Hover | `purple-900` | 正文链接 Hover |
| 引用边框 | `purple-500 / 60%` | 文章引用强调 |

创意频道的紫色目前只存在于文章阅读样式；频道首页主要依赖玻璃材质而非强品牌色。

## 七、专栏与特殊主题

### 日本行纪 / MUJI

`.theme-muji` 与 warm editorial 基线一致，并补充地图状态：

| 角色 | 色值 |
|------|------|
| 背景 | `#F0EEE7` |
| 纸张/已访问 | `#E2DBCE` |
| Hover/停留 | `#D8D0C3` |
| 墨色/木色/长期居住 | `#141413` |
| 灰褐辅助文字 | `#68645D` |
| 未访问地图 | `#CFC7B9` |

这里的“MUJI”差异主要来自排版、地图、留白和材质，而非另起一套棕色主题。

### 文章详情页

- 技术、生活：复用 warm editorial 色板。
- 金融：正文 `#444748`、标题 `#1A1C19`、链接和引用使用 `#506354`。
- 创意：背景和正文保持 warm editorial，链接与引用使用紫色。
- 未识别频道的 fallback 文章仍使用传统白/深色背景及蓝色链接，不代表四个正式频道的设计基线。

## 八、内容可视化与媒体

文章内的图表、地图、代码高亮和交互组件可以使用业务语义色，但必须与所在页面背景协调。

- 手绘技术图表的当前颜色与分层记录在 `docs/sketchy-components.md`。
- 通用图表可使用 `--chart-1` 至 `--chart-5`，但暖色频道内优先确认冷蓝色板是否适合具体语境。
- 代码高亮使用 GitHub Light 风格，并针对暖灰代码背景适配；它属于代码语法语义层，不应拿来定义普通 UI。
- 图片可以保留自身色彩；金融频道会通过灰度和 `mix-blend-multiply` 将图片纳入杂志色调。
- 状态不能只依赖颜色表达，应同时使用文字、图标、线型、形状或纹理。

## 九、代码来源与维护入口

| 范围 | 主要文件 |
|------|----------|
| 全站暖色常量 | `src/lib/site-theme.ts` |
| 全局、导航、通用 UI、暗色及频道变量 | `src/app/globals.css` |
| 首页/生活 scholarly 变量 | `src/app/home.module.css` |
| 文章频道样式 | `src/components/article/article-channel-styles.ts` |
| 首页叙事色 | `src/components/home/` |
| 技术频道 | `src/components/features/TechChannelLayout.tsx` |
| 生活频道 | `src/components/features/LifeChannelLayout.tsx` |
| 金融频道与专栏 | `src/components/finance/` |
| 创意频道 | `src/app/blog/creative/page.tsx` |
| 日本行纪主题 | `src/app/globals.css` 的 `.theme-muji` |
| 手绘图表 | `content/components/sketchy/`、`content/components/rag/` |

维护时遵循以下顺序：

1. 修改全站纸张、墨色或表面色时，先更新 `site-theme.ts` 和 `globals.css`，再检查重复硬编码。
2. 修改频道强调色时，只影响相应频道及其文章样式，不改写全站核心色。
3. 修改通用 UI 的 `primary`、`accent` 或图表 token 时，确认不会误影响内容页面中的第三方组件。
4. 新增暗色样式时，必须明确是单个组件支持暗色，还是准备扩展全站暗色主题。
5. 新增业务图表颜色时，将语义写在组件附近；形成跨文章复用后再提升为共享 token。

## 十、当前边界

- 全站已有明确的暖色编辑基线，但频道强调色尚未全部 token 化。
- 首页 `#0A0C20`、全站 `#141413` 和金融 `#1A1C19` 是三个接近但用途不同的深色。
- 通用 UI 的冷灰天蓝主题与内容页面的暖色主题并存，不能视为同一套视觉语言。
- 暗色模式不是全站完整主题。
- 多个页面仍存在硬编码色值；本文记录这些真实实现，不表示鼓励继续增加硬编码。
- 未挂载、演示或调试组件的颜色不纳入正式网站配色方案。
