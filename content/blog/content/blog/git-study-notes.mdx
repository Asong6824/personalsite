# 引言：从一次线上事故说起
这周五搞出了一个小小的线上事故，虽然叫做线上事故，但是只是我们内部测试用的一个平台，在发现问题后快速回滚，估计影响面只有一个人。

这个问题的根源其实是一次git merge操作解冲突。当时我的分支和主分支新增的更新都有对同一个文件的修改，由于主分支的修改和我的修改并不是一个部分，因此我选择保留主分支的修改。

但是我忽略的是我的修改更改了一个变量名，而主分支的修改恰好是使用这个变量，因此出现变量未找到的错误。

这个错误在开发上线的全过程中，有很多次机会可以被发现并解决，比如我在开发检查自己本地的是否是最新分支，比如解冲突的时候细心一点，比如认识到解冲突后的代码需要再测一遍。

这次事故暴露出我的git操作不够熟练，学生时代用到最多的无非是clone和push，但是在实际工作中，git的操作要复杂得多。

借此机会，我计划系统地学习git的基础概念、常用命令、协作流程与问题排查，整理成本篇git学习笔记。

# 何为 Git

中国的大学通常不会教学生什么是git。大一时，我在知乎上刷到一个帖子，那个帖子说计算机系学生想要学好计算机，最需要会用的两个工具是谷歌和github，这是第一次听说github和git。

从那之后，什么是Git？它和github、gitlab、gitee一系列带git的有什么关系？我为什么要用git？是我最迷惑的三个问题。这三个问题直到我自己动手做项目才开始有了答案。

首先是git，一句话来说，git是一种追踪对项目所做的更改，用于版本控制的工具。

Git 最初由 Linus Torvalds 创建，目的是为了对 Linux 内核的工作进行版本控制。但由于优秀的存储性能和分布式架构，git成为了现在最流行的版本控制工具。

而 GitHub、GitLab 和 Gitee 都是基于 Git 技术提供服务的平台，为 Git 项目提供远程仓库（Remote Repository）的托管服务，并通常提供额外的协作工具，如工单系统、代码评审等功能。

其中 Github 是全球最大的开源社区、Gitee 是国内特有的复制版本，就如同推特与微博的关系。

GitLab 则是一个开源的代码托管系统，GitLab 的一个独特优点是，它可以被安装在任何环境并定制扩展它，对于不想暴露自己源代码的项目极为有效，因此国内的大小互联网公司都在基于 Gitlab 搭建自己的私有代码托管平台。

说完 Git 技术和一系列平台，所以 Git 到底有什么用？我的回答是，只要自己动手做过项目，写过代码，很快就会意识到版本控制的重要性。

以一个亲身经历为例，最近的各种 vibe coding 很火，我也跟风尝试了一下，让 AI 帮忙给我的网站加几个小功能，AI 在最初表现良好，在完善几个功能后，我决定让它帮我实现一个首屏的瀑布流，最终的结果是它成功的毁掉了我首页的布局。

值得高兴的是，我一直用 Git 和 Github 管理我的网站，虽然 AI 暴走毁掉了我的现在本地存储的代码，但是我可以利用 Git 的历史回滚到我上个提交到版本，我的网站保住了！

遗憾的是，在此之前我使用 Git 从来不遵守原子提交的规范，也就意味着前面良好的修改也随着暴走付诸东流了。

但是仅此一例，就可以看出使用 Git 和遵守 Git 规范的重要性，只能说，每一个规范都有背后血痛的教训。
