“Agent” 一词在英语中的原意是“代理”。它可以是旅行社的中介、保险公司的代理，也可以是电影里的特工。无论身份如何变化，Agent 都有一个共同的核心含义——代表另一个主体去完成目标导向的行动。

在人工智能的语境中，这个词被赋予了一个更具科技感的译名：智能体。
听起来高深，但其实离我们的生活并不远。当我们唤醒 Siri 或小爱，让它帮忙查询天气、拨打电话或设定闹钟时，我们就在与一个智能体交互。

无论它的形态是文字对话框、语音助手，还是具象化的机器人，智能体的核心机制始终相同：
观察（observe）— 决策（decide）— 行动（act）。
只要一个系统能够根据环境信息做出有目的的行动，它就具备了“智能体”的雏形。这也是智能体区别于传统程序的根本所在：它不只是被动执行输入，而是能够依据环境变化主动选择行动。

事实上，“智能体”这一概念早在强化学习和机器人研究中就已出现。那时的智能体大多被设计用于特定任务，例如玩 Atari 游戏、走迷宫或控制机械臂。这些系统在封闭环境中表现出色，但一旦环境或目标发生变化，它们往往难以迁移或泛化。
于是，一个问题浮现出来——这样的智能体，真的能代表我们去完成真正的目标吗？

大型语言模型（LLM）的出现，为智能体提供了全新的运行介质——语言。
语言不仅能描述目标、规则和反馈，还能成为思考与规划的工具。
换句话说，过去我们必须为每个任务单独设计动作空间；
而如今，我们只需要让模型“想清楚下一步要做什么”，并通过语言调用工具，
就能让智能体跨系统、跨任务地运作。

这标志着智能体从被动执行走向主动推理，
也揭开了“语言驱动智能”时代的序幕。

## LLM Agent 简史

### LLM 时代前的文本智能体

在探讨 LLM 智能体之前，我们先回到更早的“文本智能体（Text Agent）”时代。
顾名思义，文本智能体是指以语言为核心进行感知与行动的智能系统。
它的“观察（observation）”与“行动（action）”都以文本形式出现：智能体通过读取文字理解环境，再以语言输出作为行动反馈。换句话说，文本既是它的“眼睛”，也是它的“手”。

事实上，文本智能体的概念远早于 LLM。早在几十年前，人工智能研究者便尝试让程序通过文字与人类交互，这一尝试孕育了两种主要的范式——符号式智能体与强化学习智能体。

1. 符号式智能体：基于规则的语言互动

上世纪 60 年代的聊天程序 Eliza 是最早的文本智能体之一。
它依靠一组精心编写的规则与用户对话——识别关键词、套用模板、重复问题。
虽然这种方法极为简单，却首次展示了“机器似乎在理解人”的错觉。

符号式智能体的核心思想，是通过人工设定的规则和符号映射来模拟智能行为：
程序先把观察到的信息转化为符号状态，再根据一系列 if–else 逻辑推导行动。
这种范式体现了早期人工智能的信念：只要规则足够完备，智能就会自然出现。

但它的局限也十分明显：

每个任务都需要重新设计规则，通用性差；

一旦环境稍有变化，系统便无法应对；

规则数量随任务复杂度爆炸式增长。
因此，这类智能体更像是专家系统，而非真正能理解语言的智能体。

2. 强化学习智能体：从规则到试错

进入 2010 年代，研究者开始在**文本游戏（Text Games）**中使用强化学习（RL）训练智能体。
在这些游戏里，智能体以文字描述观察环境——例如“你站在一间昏暗的房间里”——再以文字执行动作：“打开门”“拾起钥匙”。系统根据任务奖励调整策略，从而逐渐学会解决问题。

与符号式方法相比，强化学习智能体不再依赖手工规则，而是通过试错和奖励信号自动学习行动模式。
它体现了从“编程智能”到“学习智能”的转变。

然而，这种方法依然存在限制：

领域特异性：每个任务都需要独立训练；

奖励依赖：必须有人为定义可量化的奖励信号；

训练昂贵：大量实验与算力消耗让研究难以扩展。

这些因素使得强化学习智能体仍局限在小规模、封闭的实验场景中。

### LLM 革命

在“LLM Agent 简史与范式”的宏大背景下，来源资料明确指出了 大型语言模型（LLM）在文本智能体（Text Agent）领域所蕴含的革命性承诺。这一革命承诺主要体现在以下几个核心方面：
一、 泛化性（Generality）和少样本学习（Few-shot Learning）的能力
LLM 的核心承诺是其通用性和灵活性，这与 LLM 时代前的智能体范式形成了鲜明对比。
• 训练方式的突破： LLM 本质上是在大规模文本语料库上通过预测下一个 token 的方式训练出来的。
• 零样本/少样本能力： 然而，在推理时，LLM 却可以被提示（prompted）来解决各种全新的任务。
• 便利性和通用性： 这种能力使得构建 LLM 智能体变得非常方便，并且它们天然具有通用性。这意味着在构建 LLM 智能体时，无需进行大量的特定任务工作，即可实现通用性和少样本学习。
二、 以语言作为中间表征带来的无限维度
LLM 智能体与过去的符号式 AI 智能体和深度强化学习（Deep RL）智能体最根本的区别在于它们所使用的中间表征。
• 克服传统表征的局限：
    ◦ 符号式 AI 智能体使用符号状态。
    ◦ 深度 RL 智能体使用神经嵌入（向量或矩阵）。
    ◦ 这些传统表征通常具有固定大小的限制。
• 语言的无限空间： LLM 智能体则直接使用语言作为中间表征进行推理（即思考）。语言作为思考过程的中间步骤，提供了无限的空间。
    ◦ 智能体可以思考任意长短的内容，例如一个段落、一个句子，甚至一千万个 token。
    ◦ 这为智能体带来了无限时间尺度的全新维度。
三、 降低构建和训练的成本与难度
在 LLM 革命之前，构建智能体需要付出巨大的努力和成本，且结果往往是任务特定的。
• 符号式 AI 智能体的密集努力： 构建符号式 AI 智能体（例如为自动驾驶汽车编写数百万行规则和代码）需要密集的努力。
• 深度 RL 智能体的高训练成本： 训练深度 RL 智能体通常需要数百万个步骤，并且同样是任务特定的。
• LLM 智能体的低门槛： 由于 LLM 已经具备了丰富的知识积累，构建 LLM 智能体时只需进行**提示（prompting）**即可。这大大降低了构建通用智能体的门槛，从而有望彻底变革文本智能体领域。
四、 赋能数字自动化和更复杂、更实用的任务
LLM 智能体的出现极大地扩展了智能体可以解决的应用范围，特别是在“数字自动化”（Digital Automation）方面。
• 扩展应用领域： 传统的 NLP 和 RL 范式主要集中在问答或玩游戏等任务上。LLM 智能体则带来了新的任务维度，能够自动化数字世界中的各种事务。
• 实用性的大幅提升： 革命性的承诺在于，LLM 智能体可以帮助解决此前数字智能体（如 Siri）几乎无法解决的实用任务：
    ◦ 协助提交报销报告。
    ◦ 编写代码和运行实验。
    ◦ 查找和审查相关论文。
    ◦ 解决如 网络交互（Web Interaction，如在线购物 WebShop）或软件工程（Software Engineering，如修复 GitHub 上的 issue）等更为复杂和开放式（open-ended）的实际任务。
五、 融合推理与行动（Reasoning and Acting）的新范式
LLM 智能体带来的新范式——推理智能体（Reasoning Agent）——通过融合推理（Reasoning）和行动（Acting）的力量，展现了巨大的潜力。
• 协同作用： 以 ReAct（Reasoning and Acting）范式为例，它展示了推理可以帮助指导行动，而行动可以为推理提供实时的知识、计算和反馈。这种协同作用模仿了人类解决任务的方式。
• 内部行动： LLM 智能体最根本的创新在于引入了推理（Thinking）这一内部行动，它具有无限的语言空间，仅改变智能体自身的上下文或记忆，从而指导后续的外部行动。这种对内部思考的抽象能力，是 LLM 智能体不同于以往所有范式的核心承诺。

### 推理与行动的融合
一、 推理与行动的起源：两个独立范式的会聚
在 LLM 智能体出现初期，研究人员在 LLM 的应用中探索了两个相对独立的范式：
1. 推理范式 (Paradigm of Reasoning)：
    ◦ 核心挑战： 针对问答（Question Answering, QA）等任务，人们发现传统的 Transformer 语言模型难以直接输出正确答案，尤其对于涉及复杂计算或逻辑的问题。
    ◦ 代表方法： Chain-of-Thought（CoT）推理被引入，它是一种非常灵活和通用的方式，在推理时增强计算能力，使模型能够进行更长时间的思考，以解决更复杂的问题。
    ◦ 局限性： 纯粹的 CoT 推理缺乏外部知识或工具。即使是最聪明、最大的模型，也不知道旧金山今天的天气，或者最新的实时信息。
2. 行动范式 (Paradigm of Acting)：
    ◦ 核心挑战： LLM 需要获取外部环境知识、计算和反馈来弥补其知识和计算上的不足。
    ◦ 代表方法： 诸如检索增强生成（Retrieval Augmented Generation, RAG）、代码生成（Code Generation）或工具使用（Tool Use）等方法被提出。这些方法本质上都属于“行动”范式，因为智能体正在与各种外部环境（如检索器、搜索引擎、计算器、API 或 Python 解释器）进行交互。
    ◦ 局限性： 纯粹的行动范式缺乏推理能力。智能体仅通过模仿提示或少样本示例中的观察到行动的映射，如果遇到意外情况或需要多步骤规划时，将无法调整或重新规划。
最初，针对不同的基准和问题，研究人员提出了许多零散的（piecemeal）解决方案，例如交错使用 CoT 和检索，或生成后续问题等。然而，这种状况促使人们寻求一个更简单、统一的抽象来解决问题。
二、 ReAct：推理与行动融合的典范
这种统一的抽象，即推理与行动的融合，最终导致了 ReAct（Reasoning and Acting）范式的诞生。
• 核心理念： ReAct 的思想非常简单：同时生成推理（Thought）和行动（Action）。
• 协同作用（Synergy）： 这种融合实现了巨大的协同效应。
    ◦ 推理辅助行动： 推理可以帮助指导行动（如规划任务、调整计划、应对异常情况）。
    ◦ 行动辅助推理： 行动可以为推理提供实时的知识、计算和反馈。
• 与人类行为的相似性： ReAct 被认为是非常直观和类人的解决任务方式。人类解决任务时，会先思考（Thought），然后采取行动（Action）以获取更多知识或信息，再基于新信息进一步思考和调整。
• 机制细节： 在 ReAct 中，智能体在一个提示（prompt）的轨迹中生成“思考”和“行动”，行动会被解析并输入到外部环境中，外部环境返回“观察”（Observation）。**“行动-观察-思考”**的轨迹被追加到语言模型的上下文中，从而驱动后续的步骤。
三、 “推理智能体”的新范式：内部行动
**推理智能体（Reasoning Agent）**是这种融合的最终抽象，它从根本上重新定义了智能体的行动空间。
• 内部行动：推理（Thinking）
    ◦ 对于所有传统的智能体（如视频游戏、自动驾驶），其行动空间是由环境固定定义的（例如“左”、“右”、“上”、“下”）。
    ◦ 推理智能体引入了一种特殊的增强行动（Augmented Action），即推理（Reasoning）或思考（Thinking）。
    ◦ 推理的特性： 这种内部行动可以是任意语言，拥有无限的空间（可以是一个段落、一个句子，甚至一千万个 token）。
    ◦ 推理的影响： 推理行动不会对外部世界产生任何影响，它唯一的目的是改变智能体自身的上下文或记忆。
• 根本差异：
    ◦ LLM 时代前的智能体处理“观察到行动”的转换时，使用符号状态（Symbolic AI）或神经嵌入/向量（Deep RL）作为中间表征。
    ◦ 推理智能体则直接使用语言作为中间表征进行处理和思考。这种以语言作为中间表征的方式，带来了无限时间尺度的全新维度。
因此，推理与行动的融合不仅解决了 QA 任务中的知识和计算问题，更重要的是，它提供了一个普遍且强大的范式，可以扩展到更复杂的领域，如网络交互（Web Interaction）、软件工程（Software Engineering）甚至科学发现。这种范式将推理抽象为一种具有无限可能性的内部行动，是 LLM 智能体革命性的核心所在。

### ReAct 范式
一、 ReAct 的诞生：对分散解决方案的抽象和统一
在 ReAct 出现之前，研究人员发现 LLM 在回答问题（QA）等任务中面临多重挑战，并提出了许多针对特定问题的分散解决方案：
• 推理的局限： 纯粹的 Chain-of-Thought（CoT）推理可以增强计算能力和长期思考，但缺乏外部知识或工具（例如无法知道旧金山当天的天气）。
• 行动的局限： 基于行动的范式（如 RAG、代码生成、工具使用）虽然能提供外部知识、计算和反馈，但缺乏推理能力。这些方法往往是“零散的”（piecemeal），针对不同的基准和挑战设计。例如，直接使用特殊 token 调用工具，需要对模型进行微调，且格式不自然。
ReAct 的核心承诺就是提供一个更简单、统一的抽象来解决这些问题。它将推理（Thought）和行动（Action）这两个原本独立的范式融合在一起。
二、 ReAct 的核心机制与优势
1. 融合推理与行动（Synergize Both）
ReAct 的核心理念非常简单：同时生成推理（Thought）和行动（Action）。
• 推理指导行动： 推理可以帮助指导行动（例如规划任务、调整计划）。
• 行动辅助推理： 行动可以提供实时的知识、计算和反馈，从而为推理提供信息。
2. 轨迹和上下文机制
ReAct 通过精心设计的提示（prompt）轨迹来实现这种融合：
• 提示结构： 提示包含一个解决任务的轨迹示例，其中人类写下了思考（Thought）行动（Action）观察（Observation）。
• 迭代过程： 智能体生成“思考”和“行动”，行动被解析并送入外部环境，环境返回观察。
• 上下文积累： **“行动-观察-思考”的轨迹随后被附加到语言模型的上下文（context）**中，驱动下一步的思考和行动。
3. 类人解决任务的方式
ReAct 被认为是一种非常直观和类人的解决任务方式。
• 人类类比： 就像人类解决问题一样，智能体会先思考，然后采取行动获取更多信息或知识，再根据新信息进一步思考和调整。
• 应对异常： ReAct 的推理能力在遇到异常情况时尤其强大。例如，当搜索结果不理想或返回的不是预期信息时，推理可以帮助调整计划并指导新的行动，例如从搜索市场份额转向搜索股票价格和股票数量。
4. 泛化性和通用性
ReAct 范式不仅限于最初的问答（QA）任务，它具有强大的通用性：
• 任务转化： 许多任务，包括视频游戏中的家务任务，都可以被转化为文本游戏（Text Game）的形式。
• 广泛应用： 通过将观察结果转化为文本、将语言行动转化为原始行动，ReAct 可以用来解决网络交互、软件工程等更复杂、更开放式的任务。
三、 ReAct 在“推理智能体”范式中的地位
ReAct 实际上是**推理智能体（Reasoning Agent）**这一新范式的基础和核心。推理智能体与传统智能体的区别在于行动空间的定义：
• 内部行动： ReAct 引入的“思考”（Thinking/Reasoning）是一种增强行动（Augmented Action），它是一种内部行动。
• 无限空间： 这个内部行动可以是任意语言，具有无限的空间（可以思考任意长的内容），但它不会对外部世界产生任何影响。
• 影响自身上下文： “思考”的唯一作用是改变智能体自身的上下文或记忆（即短期记忆，如 LLM 的上下文窗口），从而影响后续的外部行动。
因此，ReAct 范式通过将“推理”抽象为一种具有无限可能性的内部行动，实现了系统性地优于仅进行推理或仅采取行动的单一方法。它标志着 LLM 智能体从简单的序列映射转向具备复杂、自导向推理能力的重大飞跃。

###
