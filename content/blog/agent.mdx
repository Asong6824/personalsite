# 引言

短短两年，人工智能世界经历了一次从“聊天机器人”到“自主智能体”的跃迁。2023 年初，大家还在惊叹 ChatGPT 的语言能力；几个月后，AutoGPT、BabyAGI 等项目掀起了“让模型自己跑任务”的热潮；再到 2024 年，各大厂在“Agent 工作流”“企业级多智能体协作”上频频发招。看似凌乱的进化轨迹，背后其实有内在逻辑：每一次浪潮都解决了前一阶段的瓶颈，也为下一次突破积累了能力。

本文尝试梳理一份大模型 Agent 的简史，回到关键节点、代表产品和技术突破，看看我们是如何从 prompt 驱动的助手，一步步走向具备感知、决策与执行闭环的自主系统。

## Agent 的基本轮廓

在讨论历史之前，先确定一个共识：Agent 不只是“大模型 + API”。典型的现代 Agent 至少包含以下能力模块：

- **感知**：通过文本、图像、结构化数据等输入理解当前环境。
- **记忆**：将历史对话、任务状态、外部知识持续写入一个可检索的记忆体。
- **决策**：根据目标和上下文选择下一步行动，可能是调用工具、编写代码或与其它 Agent 协作。
- **行动**：执行 API 调用、运行脚本或与人类反馈循环互动。
- **反思**：评估执行结果，必要时调整计划或生成新策略。

这些模块在不同阶段的 Agent 实现中权重各异。早期的助手靠 prompt 即兴发挥，几乎没有记忆与反思；如今的产品更强调计划、协作和可控性。

## 时间线上的关键节点

### 2017-2021：堆叠能力，为 Agent 埋下伏笔

- **2017 年**，Transformer 论文发表，统一了现代大模型的架构基础。
- **2019-2021 年**，GPT-2、GPT-3、T5 等大模型陆续发布，语言生成质量跃升，Prompt Engineering 一词开始流行。
- **工具调用雏形**：微软、谷歌在研究中探索让模型读 API 文档、生成调用参数的可行性，但距离真正的自主 agent 还很远。

这个阶段的重点是“具有通用语言能力的模型”逐渐成熟，为后续构建 Agent 提供了认知基础。

### 2022：指令对齐与函数调用，约束模型行为

ChatGPT 的爆红不仅来自对话体验，更关键在于 **指令微调**（Instruction Tuning）和 **人类反馈强化学习**（RLHF）。模型第一次学会按照人类的自然语言指令执行任务。此外，OpenAI 与微软在 Copilot 中探索了“工具调用 + 代码执行”的模式，证明模型可以被约束在一个明确的决策空间内执行任务。

### 2023 上半年：AutoGPT 带来的自治幻想

- **AutoGPT / BabyAGI**：借助 GPT-3.5/4 的函数调用能力，把“规划、执行、反思”流程自动化。虽然经常卡住或跑偏，但它们让大众第一次看到 Agent 的潜力。
- **LangChain 与工具生态**：LangChain 把 prompt、工具、记忆封装为模块化组件，短时间内成为构建 Agent 的主流框架。
- **研究突破**：ReAct、Toolformer 等论文系统性地探讨了“把推理链与动作结合”以及“模型自学 API 调用”的方法。

这一阶段的 Agent 仍然脆弱，但“自主 + 环境交互”的范式已成共识。

### 2023 下半年：工作流与企业落地

- **函数调用标准化**：OpenAI、Anthropic 接连发布结构化函数调用接口，更易于控制模型行为。
- **工作流变得可视化**：微软 AutoGen、Dust、TaskWeaver 等产品把 Agent 组合成流程节点，可插拔地拼接计划、工具、人工校验。
- **企业内 Agent**：Notion、Salesforce 等公司开始把 Agent 用于客户支持、销售助手和研发提效，强调“人机协同、可审计”。

从这一阶段开始，“Agent = 能跑完业务闭环”成为新的评价标准。

### 2024：多模态与多智能体协作

- **多模态 Agent**：GPT-4o、Gemini 1.5、Claude 3 等模型支持视觉、音频，使 Agent 可以处理真实世界的输入，更贴近机器人控制、客服质检等场景。
- **多智能体系统**：Meta 的 CAMEL、Stanford 的 OASST 等研究探索“多个角色分工合作”的模式，涌现出如 CrewAI、Voyage 等框架，将角色设定、通信协议、仲裁机制产品化。
- **记忆与个性**：MemGPT、LangGraph 提供结构化记忆与状态机，让 Agent 在长周期任务中持续保持上下文，而不是每轮都从零开始。

这时的 Agent 越来越像“软件中的软件团队”，需要组织结构、权限控制和监控体系。

### 2025 前夜：原生 Agent 模型与操作系统化

- **原生 Agent 模型**：OpenAI rumoured Orion、百度文心 Agent、阿里通义千问 Agent 等产品强调模型内部加入计划器、反馈器，让“决策-执行-回顾”成为内建能力。
- **Agent OS 思想**：像 Cognition 推出的 Devin、xAI 的 Grok Agent、Rabbit R1 等尝试打造“AI 原生操作系统”，模型直接驱动浏览器、终端甚至物理设备。
- **安全与评测体系**：包括 GAIA、AgentBench 在内的基准出现，企业开始重视可控性、成本和安全，不再迷信简单地“撒模型”。

Agent 这个概念终于从实验室的概念验证走到了产品路线图的中心。

## 关键技术积木

- **记忆机制**：向量数据库、RAG、Memory Stream 等技术让 Agent 能够积累经验；没有记忆，自主性很快崩溃。
- **规划与执行解耦**：Planner-Executor、Tree-of-Thought、Graph-of-Thought 提供了结构化思考方式，降低模型反复试错的成本。
- **工具生态**：函数调用、OpenAPI 接入、代码解释器、浏览器控制器等，让模型具备真实世界的“手脚”。
- **监控与评测**：从神经网络的 logprob 到专门的守卫模型（Guardian Model），帮助我们判断 Agent 是否安全、可靠。

这些积木之间的组合方式，决定了一个 Agent 是否“可控又有用”。

## 为什么大模型 Agent 依旧困难

1. **幻觉与可靠性**：模型依旧可能自信地给出错误答案，需要额外的验证与冗余检查。
2. **成本与延迟**：一个复杂 Agent 的调用链可能包含数十次推理和工具调用，成本高昂且响应慢。
3. **环境不稳定**：API 变动、权限受限、网络失败都会导致流程中断，Agent 必须具备恢复和降级策略。
4. **人机协作边界**：哪些环节需要人工确认？如何把 Agent 的决策解释给人类？这些都是落地时最常见的难题。

真正成功的 Agent，往往是“把自主与可控做平衡”，而不是一味追求全自动。

## 展望：从工具到伙伴

未来一两年，Agent 可能沿着三条线路继续演化：

1. **垂直行业化**：聚焦在客服、游戏、金融风控等明确场景，针对领域知识做深度调优。
2. **人机混合工作流**：把 Agent 当作“团队成员”，通过权限、审计和协作工具把人类拉进闭环中。
3. **硬件载体与原生体验**：从桌面操作系统到 AR、智能硬件，让 Agent 直接成为用户的操作界面。

无论终局如何，可以确定的是：Agent 不再是某个特定产品的名字，而是一套组织生产力的新方式。理解这段简史，有助于我们在快速迭代的浪潮中找到自己的定位——是追逐新名词，还是沉淀能力积木，构建真正可持续的智能系统。
